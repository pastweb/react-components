# React Components

Interactive documentation for the public React renderers built on the
framework-neutral behavior and style contracts from `@pastweb/components-core`.

## Installation

Install the React renderer package:

```bash
pnpm add @pastweb/react-components
# or
npm install @pastweb/react-components
# or
yarn add @pastweb/react-components
```

`@pastweb/react` and `@pastweb/components-core` are peer dependencies.

## Using these docs

Each component page includes:

- tabbed source for the React implementation, public types, constants when
  present, and barrel exports;
- an interactive preview with controls for props and supported utility
  classes;
- responsive viewport options in the preview toolbar; and
- accessibility checks through the Storybook accessibility panel.

Component styles come from `@pastweb/components-core`. Shared CSS variables
and document foundations are loaded once for every preview, while each story
renderer loads its component-specific CSS module.

## Accessibility standards

Components use native HTML controls and document structure whenever the browser
already provides the required behavior. Buttons, inputs, links, labels,
headings, lists, landmarks, dialogs, and form controls keep their native
semantics rather than recreating them with generic elements and ARIA roles.

The renderers follow <span className='accessibilityStandard'>WCAG 2.2 Level AA</span>,
the relevant <span className='accessibilityStandard'>WAI-ARIA Authoring Practices</span>
pattern, and applicable <span className='accessibilityStandard'>GOV.UK Design System</span>
guidance for each component. They provide accessible names and IDs,
keep ARIA state synchronized with component state, preserve keyboard operation
and focus order, expose visible focus indicators, and keep hidden or inactive
content out of keyboard navigation. Modal components contain and restore focus;
interactive controls use native keyboard behavior; and status content uses the
appropriate live-region semantics.

Shared styles respect `prefers-reduced-motion` and forced-colors preferences.
Automated Storybook accessibility checks support review, while component pages
document any interaction requirements that need manual verification.
